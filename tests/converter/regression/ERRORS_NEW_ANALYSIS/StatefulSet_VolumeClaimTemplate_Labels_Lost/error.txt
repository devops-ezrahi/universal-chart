- THIS BUCKET CONTAINS TWO DIFFERENT THINGS AND THEY MUST BE SPLIT — the counts blur them together, which is why the same field path appears in both the "suppress" and "fix" columns:
  1. RUNTIME BOILERPLATE — status, kind, apiVersion, creationTimestamp (~17-28 instances). GENUINELY BENIGN. status: {'phase': 'Pending'} is server-populated runtime state that must never be in a chart; kind/apiVersion on an embedded template are redundant. SUPPRESS these.
  2. LABELS — spec.volumeClaimTemplates[].metadata.labels (1+ instances). A REAL LOSS with a stated business consequence: PVCs created by the StatefulSet carry no team/environment labels, so they cannot be tracked, quota-managed or cost-allocated. FIX this.
  Suppressing the whole path would silently bury the labels defect inside the boilerplate suppression. Write the suppression rule against the specific runtime keys, never against the whole volumeClaimTemplates subtree.

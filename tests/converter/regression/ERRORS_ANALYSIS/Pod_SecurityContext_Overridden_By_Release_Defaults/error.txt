ADDITIONAL CONTEXT / CLUES:
- Scope/altitude bug: a per-resource (and per-container) field is being flattened into one release-level value, so the last writer wins and the defaults.yaml value (2000/2000) usually survives.
- Capture point that exists but is mis-scoped: convert_to_universal_chart.py line 852 (per-container podSecurityContext).
- Capture point that is entirely missing: CronJob/Job pod-level securityContext (handle_cronjob / handle_job).
- Chart side: .Values.podSecurityContext and defaults.yaml (2000/2000).
- Affects Deployments, DaemonSets, CronJobs and Jobs (report issues 6, 15, 24, 39).
- Functional impact: running as UID 2000 instead of 1000 breaks file ownership on mounted volumes and can make containers unable to read their own data.
- conflicts_and_warnings.txt also logs "securityContext: {} | 109 | Empty security context" as a separate, harmless empty-map loss — do not confuse the two.

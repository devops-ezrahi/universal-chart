ADDITIONAL CONTEXT / CLUES:
- Root function: split_image in convert_to_universal_chart.py — it parses repository/tag but does not recognize the @sha256:<digest> form, so the digest is discarded and the fallback tag (Chart.AppVersion = 2.0.0) is substituted.
- Related function in the same area: named_list_to_map_split_image() at convert_to_universal_chart.py:528.
- Count discrepancy across two tables in the report: the severity table says 9 workloads, the CHANGED field table says 31 occurrences of containers[*].image — the higher number includes sidecars/initContainers.
- The fix must preserve the digest form in values (image.digest) and the chart's universal-chart.image helper must emit repository@sha256:digest when a digest is present instead of repository:tag.
- Functional impact compounds with the imagePullPolicy downgrade: a pinned-by-digest workload becomes pinned to a mutable tag AND stops re-pulling — the deployed binary is effectively unpredictable.
